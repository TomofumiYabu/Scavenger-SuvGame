# 技術構成

## AL-033 計画表示と説明欄の保持

ルートの部品予算は `missionDetails()` の修理/送信費用から、回収画面の空き容量は既存のBigIntによる使用容量から導出する。画面間移動は既存のpanel/show-ground操作だけを使い、物資移動を自動実行しない。

`model.ts` の `minimumMoves(from, to)` は既存の `neighbors()` を幅優先で辿る純粋な参照関数とする。移動可能な全49地点に対する最短回数であり、探索・補給・イベントの発火や解決をシミュレーションしない。実際の行動・発見・乱数・保存に影響しない。

行動案内では、変動する理由・危険・要約・見込みを固定の `.action-summary` の中へまとめ、後続の `details` の兄弟位置を保つ。DOM更新方式は変更せず、説明の開閉状態を維持する。短い横長画面の固定ヘッダーだけをCSSでコンパクトにする。

## AL-032 行動後の見込みと操作の復帰

見込みの通常値は既存の `assessAction().after`、負傷時の体力は同じ行動条件と `projectStats()` から導出する。UIで費用ルールを再定義せず、乱数や保存状態を変更しない。読み上げ説明にも同じ値を含める。出来事への復帰は既存の `data-panel="encounter"` を使い、固定の `pending-navigation` 領域内で表示を更新する。スクロール外の現在値・未保存警告を維持する。

復旧失敗後は再描画した復旧ボタンの `disabled` を確認し、無効ならフォーカス可能な復旧 `summary` を表示する。`SaveStore` の読取・退避・書込処理やデータ形式は変更しない。

## AL-031 行動案内の表示境界

案内は既存の移動先・探索方法・探索可否・待機イベント状態から導出する読み取り専用表示とする。該当する生存/期限内/未解決条件を満たす時だけ予告を示し、探索要約には探索後イベントの有無と慎重探索の利点を含める。保存状態は既存の保存機構の結果から導出し、drawerのscroll外に未保存表示と保存確認導線を保ち、失敗原因の詳細は設定paneで読めるようにする。イベント待機中に通常行動を有効化したり、保存処理・ゲーム状態・保存形式を変更したりしない。

## 採用

### AL-030 UI表示境界

AL-030では既存game stateからの読み取り専用表示を追加し、確定行動や保存状態は増やしていない。選択地点の地面情報は既知地点に限り、回収は現在地のみ。ステータスshortcutは目的操作または説明へのfocus移動に留め、自動実行しない。ゲームルールと保存形式は変更していない。

保存互換の将来要件は設けない。異なる版間の移行、過去ルールの再現、歴史的fixtureの固定化は新たに要求しない。ここに記す旧版対応は現行実装の説明である。現行版の保存・再開・バックアップと、破損/非対応データを保護して案内する挙動は維持する。保存仕様を変更する場合は同版の保存・再開を検証し、必要に応じて版を判別して非対応を案内する。

| 要素 | 選択 | 理由 |
| --- | --- | --- |
| 言語 | TypeScript / strict | 状態、行動、セーブ形式を型で明示できる |
| UI | HTML + CSS + SVG | ターン制マップと情報パネルに適し、キーボード操作やレスポンシブ対応が容易 |
| 開発・配布 | Vite | 軽い開発サーバーと静的ファイルへのビルド |
| ルール検証 | Vitest | DOM なしで行動・資源・勝敗・保存検証をテスト |
| 操作検証 | Playwright + Cloud 標準 Chromium | ビルド成果物の実操作、保存復元、モバイル幅を確認 |
| 保存 | localStorage / schema 2・content 8 | バックエンド不要。端末間同期は対象外 |

Node.js 24.19.0 / npm 11.9.0 を Cloud で使用。npm キャッシュは `.npmrc` でチェックアウト内の無視対象 `.cache/npm` に配置する。新規導入で lockfile を作成し、以後 `npm ci` で再現する。

React などの UI フレームワークや Phaser / Godot は、現段階の小さなターン制 UI には導入しない。アニメーション、戦闘、広いマップが必要になった時点で再評価する。ルールと UI の分離によって描画方式を変更しやすくする。

## 状態と処理

`src/game/items.ts` は8種のID・名称・既存SVGの参照名・整数容量・説明・回復・使用可否・負傷治療の `treatsWound` を定義する。ゲームルールとUIは同じ定義を参照し、`model.ts` は互換用に `Item` と `ITEM_NAMES` を再エクスポートする。アイテム定義はモデルを実行時にimportしない。所持数の保存は従来と同じ数値で、合計容量だけを `inventoryLoad()` と `capacityChange()` がBigIntで導出する。個別の数量が安全な整数でも合計容量は超え得るため、通常のnumber加算に丸めない。BigIntはGameState/JSONへ追加しない。

入力 → `act(state, action)` → 新しい状態 → 保存 → 再描画。ルール関数は入力を変更しない。不可能な行動は状態を変えない。乱数は状態に保持するシード付きの疑似乱数で、進行中の乱数状態を保存する。`newGame(seed = 2026)` は決定的に状態を作り、テストでは固定シードを指定する。ブラウザでの新規開始・リセット用シードは新規状態生成factoryから注入し、`SaveStore` はfactoryを利用して保存処理と乱数源を分離する。未探索地点と探索済み地点を別々に管理する。

`src/game/mission.ts` はルール世代を識別する `Mission` 判別型と、relay-v1用の中継所/送信条件を定義する。新規開始はA2（tile 7）またはG6（tile 41）のどちらか一方を修理し、G1で送信する。A2は4時間・スクラップ4・気力24/満腹度12/水分16、G6は2時間・スクラップ6・気力16/満腹度8/水分12。送信は2時間・スクラップ4・気力12/満腹度6/水分8。`missionDetails(state)` はrelay-v1にだけこれらを返す。旧保存の `legacy` は修理不要で、送信1時間・スクラップ3・満腹度3/水分4を維持する。`GameState.mission.repairedRelay` は未修理nullか、修理済み地点IDを保持する。

`src/game/actions.ts` の DOM に依存しない `actionTerms()` に、時間、能力値の消費・回復、所持品の消費、バックパックへの追加、地面への追加、負傷率、乱数更新の有無、負傷治療 `treatsWound`、追加気力 `woundEnergyCost` を集約する。`src/game/mission.ts` は中継所2地点の選択肢、修理費、救難信号の費用、旧ルールと新ルールの `Mission` 判別型を定義し、行動の値は `missionDetails()` 経由で参照する。`SEARCH_METHODS` は探索2方式の表示名・時間・費用を定義し、地形ごとの通常収穫と慎重な探索の既存の追加1個・新アイテム1個から実際の収穫を作る。`search.mode` は `quick` / `careful`。従来の内部呼び出しで省略した場合だけ `quick` とし、不正な方式は拒否する。コントローラーのDOM入力には有効な明示方式を必須とする。`assessAction()` は同じ値から実行可否・不可能な理由・状態に応じた危険・負傷を含まない確定的な行動後の能力値を返す。`canAct()` とUIの disabled / 説明表示はこの判定を共用し、`act()` は同じ費用・回復値を適用する。共通の純関数 `projectStats()` が上限までの回復、負傷、時間で等分した毎時の消費と、各時間の消費後に0になった満腹度・水分それぞれの体力−12を計算する。従来の1時間行動と0時間の立ち去りの結果を維持する。`pickup` / `drop` は `item` と正の安全な整数 `quantity` を取り、0時間・能力値消費なし・抽選なしとする。0時間では空腹・渇きの体力減少も発生しない。2時間の探索も全時間・収穫・探索済みを一括確定し、途中状態のUI・保存・中断は導入しない。死亡、送信成功、時間切れの順に解決する。`repair` は新しいルールセットでA2またはG6の未修理中継所に限り、一度だけ実行できる。`signal` は新ルールでは修理済み中継所を要求し、旧ルールでは従来どおり通信塔で実行する。必要時間が残り時間を超える行動は拒否し、ちょうど48時間の終了は許可する。手早い探索は従来どおり全地形で乱数を1回進め、廃墟でだけ3分の1の負傷を判定する。慎重な探索は負傷抽選・乱数更新をしない。イベントの危険な選択の乱数更新も維持し、案内では乱数を参照しない。プレビューは入力を変更しない。

`src/game/wounds.ts` は `Wound`（`none` / `minor`）、表示名、毎時の追加気力2、保存検証の型ガードを定義する。`GameState.wound` は新規開始で `none`。抽選成功は従来の即時体力−10と同時に `minor` を残し、再負傷の体力損失は維持するが状態は重複しない。`actionTerms()` は行動開始時の状態から移動・探索だけに `hours * 2` を加え、`woundEnergyCost` にその追加分を返す。`costs.energy` は既に追加分を含むため、UIやエンジンで再加算しない。新たな負傷によって同じ行動の費用を変更しない。イベント選択・休息・使用・送信・0時間操作には負傷の気力加算がない。毎時の出血、自然悪化・自然治癒もない。

`ActionTerms.treatsWound` は現在の負傷有無と独立した行動の治療能力。物資定義（包帯/救急キット）、イベント選択定義（処置台の治療/熾火の睡眠）、避難所の通常休息から求める。UIはIDを列挙せず同じ値を案内に使う。エンジンは共通の費用・回復を反映し、実行できた治療で `none` に戻して日本語ログを記録する。体力100でも合法で、元の所持条件・時間・消費は維持する。避難所以外の休息、食事・飲料、包帯をフィルターにする選択、単なる体力回復は負傷を消さない。終了解決より前に負傷/治療を確定し、終了状態もそのまま保存する。拒否された行動は元の参照を返し、負傷・所持品・乱数も不変。

`ActionTerms.rewards` は所持品への追加（拾う操作）、`groundRewards` は現在地の地面への追加（探索・イベント・置く操作）、`supplies` は所持品の消費（使用・送信・イベント・置く操作）を表す。`assessAction()` は現在容量・所持品の差分・行動後容量をBigIntで返す。拾う時は24以下が必要で、旧データの過積載は全数量を保持して容量を減らす操作を許可する。探索・イベントの収穫ではバッグの容量は増えない。DOM由来の不正IDや数量は項目の計算前に検証し、BigInt変換で例外を起こさない。所持品と地面の追加先が安全な整数を超える時は行動全体を拒否する。

`GameState.mission` は `{ ruleset: "legacy", repairedRelay: null }` または `{ ruleset: "relay-v1", repairedRelay: null | 7 | 41 }` を持ち、ルール世代と修理地点を保存する。`newGame()` はrelay-v1・content8の状態と新しい開始能力値/物資を生成する。`newLegacyGame()` はテスト用に従来開始状態を生成する。

`GameState.ground` は地点IDから物資ID/数量への疎な記録。新規開始は空で、`act()` は構造を複製してから現在地だけで数量を移す。拾う時の地面の減算はエンジンが担当し、0個になった項目と空の地点を削除する。探索・イベント・置く操作は共通の `groundRewards` を適用する。通常探索とイベント解決は一度だけで、移動・読込では収穫を作らない。終了した探索も地面の収穫を確定する。未解決イベント中と終了後は移動と同様に拾う・置く操作も拒否する。拒否は複製・時間・乱数・収穫・探索済み・イベント解決より前に行い、元と同じ状態参照を返す。コントローラーも同じ参照なら保存/再描画をしない。

UIは費用・実行できない理由をボタンの近くに表示し、回復・危険の詳しい説明は開閉式にまとめ、`aria-describedby` で関連付ける。探索の各方式は別々の `data-focus="search-quick"` / `search-careful` と `guide-search-quick` / `guide-search-careful` を持ち、DOM更新で異なる方式に同じボタンを流用しない。ネイティブの disabled ボタンを維持し、使用不能になった操作は近くの説明へフォーカスを移す。所持品メニューは8種と使用容量/24を示し、容量超過時は保持した所持品と拾えない条件を通知する。現在地の物資を1個ずつ、または容量に入る分だけ拾い、所持品は1個ずつ現在地へ置ける。未選択分は地点に残す。地面の各項目は固定の要素を保持し、0個の項目は隠す。最後の物資を拾った時は可視の地面欄の見出しへフォーカスを戻す。各カードの用途・1個容量と、容量が変わる行動の差分/行動後容量も同じ定義と判定から描画する。所持不足で負になる試算は表示しない。容量警告は常設の `data-region="capacity-warning"` の内部だけで追加/削除し、過積載から上限以内へ戻っても所持品グリッド・使用ボタンのDOMを保持する。長い旧保存所持数も折り返す。狭幅では所持品カードを1列にして、費用・回復・理由が折り返して読める幅を確保する。

マップは上頂点型六角形の odd-r offset（0始まりの奇数行を右へ半セル移動）。`neighbors()` を移動判定・発見・UIに共用する。IDは従来どおり `y * 7 + x`、座標名はA1〜G7で地形配置も維持する。UIはHTMLボタンを六角形にクリップし、幅の半分の行オフセットと高さの3/4の行間隔で敷き詰める。SVGの六角形線で選択状態とキーボードフォーカス（破線）を表示する。各ボタンは座標・現在地・探索済み・隣接状態を読み上げ、隣接地点には＋印も表示する。

現行のゲーム画面は `#game` を `100dvh` に合わせ、ヘッダーと能力値/目標の帯の下でマップを主役として広く表示し、下部のドックを固定する。ドックから「地点」「所持品」「目標」「記録」「設定」を開ける。地形タイルをクリックすると、選択地点の画像・説明・行動を載せた右側のモーダル・ドロワーが開く。ドロワーには暗幕、閉じる操作、Escapeで閉じる処理、Tab/Shift+Tabのフォーカス循環があり、開く前のボタンへフォーカスを戻す。狭幅では下から開くドロワーに切り替える。画面高が650px以下では `#game` を通常フローに戻して縦スクロールを許可し、マップの読めるセル寸法と固定ドックを保ち、ドロワーは画面内に収める。マップには未発見の霧、現在地、隣接の＋、探索済み印、地点の物資印、通信塔と新規ルールの2中継所を表示し、未発見地点は無効化する。保存形式やゲーム状態を変えず、選択中地点だけでパネルを切り替える。ヘルプダイアログは開くたびに見出しへフォーカスし、先頭から表示する。

`public/art/terrain-atlas.webp` は6地形の3列×2行の画像スプライト、`public/art/city-backdrop.webp` はマップ背景に使う。地点のドロワーでも同じ地形画像を表示する。両素材はこのプロジェクト用に生成した画像で、プロンプト、配置、表示寸法、ファイルサイズ、作成元を `docs/ART_ASSETS.md` に記録する。配信するWebP画像の合計は814,318 byte。

`src/game/events.ts` は独自イベント6件の地形・文章・選択ID・費用・回復・物資消費・収穫・負傷有無・負傷治療 `treatsWound`・結果・一度だけの出現方針を定義する。`trigger` は `move` / `search`。`eventForTerrain(terrain, trigger = "move")` で発生を選び、`eventById()` / `eventChoice(eventId, choiceId, searchMode?)` で保存・描画・判定を共用する。`EventChoice.careful` は説明・時間・費用・収穫・結果の上書きだけを持つ。`eventChoice()` は上書きした実効値を複製して返し、共有定義を変更しない。`actionTerms()` と選択時のログ、UIの案内と結果は、待機の方式から同じ実効選択肢を取得する。`searchHint` は探索前に示す慎重な探索の利点を持ち、定量的な費用は共通判定から描画する。

エンジンは移動・探索を全て適用し、死亡・時間切れを判定した後、生存・時間内かつ未解決の該当イベントだけを待機にする。元の廃墟・診療所・避難所は移動時、新しい道路・緑地・通信塔は探索時だけ発生する。探索の費用・乱数・地面収穫・探索済みは先に一度だけ確定し、選択で再適用しない。待機はイベントIDと現在地点に加え、探索イベントだけ `searchMode` を必須とする。省略した内部探索入力は `quick` を保存する。解決履歴はイベントID単位で、同じ地形の別地点にも適用する。`assessAction()` は未解決中の通常行動と古い選択を拒否する。物資消費は所持品だけ、収穫は地面だけを使う。0時間の立ち去りと慎重な探索後の追加作業は、空腹・渇きの体力減少も抽選も行わない。通常探索の乱数更新と備蓄庫の危険な選択は従来どおりで、他5件の選択は乱数を使わない。避難所はSTART/B6の1か所だけなので、新規開始では発生せず最初の帰還移動で発生する。

`src/game/recap.ts` は `RunRecap` / `RecapEntry` / `RecapAction` / `RecapSnapshot`、記録・検証と純粋な `buildRecapReport(state): RecapReport` を提供する。`GameState.recap` はnullまたは `{ startedAt, entries }`。エンジンは勝敗とイベント待機を確定してから、拾う/置く以外の確定行動を記録する。省略された探索方式はquickへ正規化し、選択は行動前の待機のsearchModeを保持する。先行状態を複製した新状態の履歴へ追加するため、過去状態を変更しない。時間を使う行動48件と一度だけのイベント選択6件で54件以下に収まり、無制限な0時間の物資移動は対象外。切り詰めによる情報損失は生じない。

`projectStats()` は従来の `after` と名目上の `depletion` に加え、上限で実際に減った体力の `damage: { injury, hunger, thirst }` と `fatalCause` を返す。回復→負傷→各時間の消費→空腹→渇きの順を維持し、最初の正の体力から0への遷移だけを直接の原因とする。ログ・プレビューの名目損傷は変更しない。記録の `before/after` は能力値4種とwound、`from/to` は地点、`fromTurn/toTurn` は経過時間。RNG、所持品、地面を履歴へ複製しない。

`validateRecap()` は厳密な既知キー・ID・整数範囲、1〜54件、開始時刻、記録間の時刻/地点/能力値の連続、既知のイベントと選択/探索方式、重複探索・重複選択の禁止、許された時間・能力値・損傷・治療と最終状態の一致を検証する。content8では中継所の `repair` を行動記録として許可し、記録された修理地点がmissionの `repairedRelay` と一致すること、新ルールでは送信前に修理が記録されていることを確認する。既存の `actionTerms()` / `projectStats()` で確定的な能力値を確認するが、所持品や乱数を再実行しない。未知のIDはunsupported、既知形式の不整合はcorruptに分類する。v1とcontent1〜6のrecap不在または余分なnullはnullへ移行し、過去の行動を生成しない。content7のrecapはlegacyルールとして保持・検証し、content8の新規プレイではrelay-v1の行動費用と修理、B6・初期能力値から始まる途切れのない履歴を検証する。v1/content1〜6の非null recapはunsupported。content6/7/8はwoundが必須で、minorも維持する。nullは旧終了状態・未記録の途中状態でも合法。読込時に書き込まず、旧content1〜7の原文も初回保存前の永久退避対象に含める。費用・回復・危険のルールを変える際に、保存済み異版の履歴を解釈する互換検証や版付き移行を新たに用意する義務はない。変更後は現行版で作成した保存の再開を確認し、非対応形式は版を判別して案内する。

`buildRecapReport()` は終了理由、最後の行動/実損傷、記録された時間範囲、全行動の時間集計、主要な経過、最大3件の次回への助言を返す。死因は最終記録のfatalCauseだけを使い、最終資源や日本語ログから推測しない。途中記録・未記録は明示する。現行の定義から日本語の行動名を導出し、休息/物資使用/選択/探索は主要な経過へ含める。UIの `recap.ts` が文字列をエスケープして終了欄へ表示し、開閉できる内訳と経過を提供する。助言は原因キーで順序を決め、直接の死因または時間切れを優先する。負傷の助言は直接の致死行動、なければ直近の負傷行動の構造化データから、備蓄庫の奥の選択と廃墟の手早い探索を区別する。日本語の接頭辞を使って原因を並べ替えず、別行動での成功を保証しない。

保存はschema 2・contentVersion 8で、キーは従来の `afterlight.save.v2` を維持する。`save.ts` の `decodeSave()` はストレージに触れず、正常・旧版移行・破損・非対応を区別する。`deserialize()` はゲーム状態またはnullを返す互換窓口。値域、配列、勝敗、現在地、待機と解決履歴、既知のイベントIDと所持品IDを検証する。content6/7/8は既知の `wound` が必須で、欠損/文字列以外は破損、未知の文字列は非対応。v1とcontent1〜5ではフィールド不在または余分な `none` を `none` に移行し、体力から負傷を推測しない。旧版の `minor` や未知の文字列は非対応、他の不正型は破損として保護し、条件を黙って捨てない。内容版3〜8では8種、旧v1とv2/内容版1/2では旧4種の所持数すべてを必須にする。未知の所持品IDは非対応、欠損・負数・小数・安全な整数以外は破損とする。容量超過は破損とせず全数量を保持する。待機は現在地・対応地形・active・未解決を必須とし、探索イベントは現在地の探索済みと有効な方式も必須、移動イベントは方式を禁止する。欠損・構造不正は破損、未知の方式名は非対応とする。解決IDは一意で、最大件数を対応する定義から導く。内容版1は備蓄庫だけ、2〜4は明示した元の3件のIDだけ、5/6/7/8は全6件を許す。未知の内容版/イベントIDと、その内容版で未導入のIDは非対応として保護する。

旧版を読み取る時はcontent8を返し、保存には触れない。旧v1とcontent1〜7からの移行状態は `mission.ruleset: "legacy"` とし、旧版の送信条件・費用を引き継ぐ。content7の既知の振り返り履歴は変更せず、旧データを新しい修理ルールで再解釈しない。v1は元の資源・時刻・乱数・ログ・勝敗を保持して待機なし・解決履歴なしを補う。v2/content1〜7は待機・解決履歴を含む全進行を保持する。v1とv2/content1・2は追加4種を0で補い、content3以降は8種を保持する。content3以前の地面だけを空とし、content4/5/6/7の地面は空の記録・0個・安全上限の数量も含めてそのまま引き継ぐ。content4/5/6/7/8の地面は必須で、正規の文字列表現の地点ID（0〜48）、発見済み地点、既知物資、非負の安全な整数を検証する。未知の地面の物資IDは非対応、それ以外の構造・数量の不正は破損とする。追加先が安全な整数を超える行動は拒否する。現在地の六角形隣接発見は全対応版で冪等に補完する。読込で乱数を進めたり、過去の収穫や新イベントを作ったりしない。旧版の探索済み地点も再探索できない。

`src/game/storage.ts` の `SaveStore` がストレージだけを担当する。読み込みはv2を優先し、存在するv2が不正/非対応ならv1へ戻らない。不正な原文は保護状態にして通常保存を止め、メモリ上の新規プレイを許す。読み込み自体は書き込まない。候補データを検証してから、読み取り可能な前のv2原文（旧内容版も可）を `.backup` へ書き、読み取り一致を確かめて主保存を更新する。v1移行直後は移行した初期状態をv2形式でバックアップしてから初回保存し、元v1原文は触らない。v2/content1・2・3・4・5・6・7を初めて更新する前は、原文を `.original.<連番>` へ永久退避し、読み取り一致を確認してから通常のバックアップ・主保存の書き込みへ進む。保存を重ねても退避は増やさず、失敗後の再試行でも同一原文の検証済み退避を再利用する。退避やバックアップの失敗なら主保存を変更しない。別タブなどで主保存が読み込み時から変わった場合も保護する。

復旧は検証済みバックアップ（読み取り時に移行する旧版も可）を対象とし、UIの確認後に実行する。復旧/新規探索で主保存を切り替える際は、その時点の原文を `.original.<連番>` へ退避し、読み取り一致の確認後だけ主保存へ書く。既存退避と旧v1は消さない。読み込み/書き込み/読み取り確認の失敗時は通知し、通常保存を停止する。localStorageの書き込み単位の原子性を利用し、複数キーのトランザクションは仮定しない。主保存の書き込み後の確認が失敗した場合は切り替え完了を保証せず、元データをバックアップ/退避に保持する。複数タブ間の競合を完全に排除する同期機構は持たない。

UIは `src/ui/controller.ts` が明示的なゲーム状態・選択地点・UI専用の結果と `SaveStore` を保持する。`main.ts` は起動だけを担当する。`templates.ts` は渡されたコンテキストから画面と行動案内を作り、起動時のダイアログシェルを提供する。`render.ts` はネイティブDOMを差分更新し、変更のない要素を保持する。通知・終了・イベント/結果には固定の領域を用意し、その追加・削除で後続のマップや所持品を置き換えない。要素名とID・操作キーが変わる要素は交換し、異なる操作へ同じボタンを流用しない。属性・テキスト・子要素だけを必要に応じて更新する。`details.open` はライブDOMに保持し、保存不能へ変わった時だけコントローラーが説明を開く。フレームワークと追加依存は使わない。

`focus.ts` は実際の操作ボタン・操作キー・関連説明・近くの領域とスクロール位置を記録する。通常更新は存続する操作へ `preventScroll` で戻し、上部の結果が消えた場合も対象の画面内位置を補正する。ボタンがdisabledなら関連説明、削除されたら地点の行動領域などへ戻す。代替対象が画面外なら最小限表示する。イベント/結果/終了の見出しと明示的なマップへ戻る操作は、フォーカスとスクロールを意図的に移動する。ネイティブダイアログのキャンセル/閉じる時は実際の起動ボタンと位置を復元し、リセット/復旧確定時は復元を抑えて読み込んだ状態へ移す。

`outcome.ts` はイベント定義から選択名と結果文を取得し、実際の前後のゲーム状態から時間・能力値・所持品と現在地の地面の差分を区別して作る。ログはエンジンのstructuredCloneで参照が変わり12件に制限されるため、前ログの先頭と後ログの末尾の最大一致をturn/text/kindで比較し、新しい危険だけを取り出す。単なるログ件数差を使わず、0時間の選択でも過去の危険を再掲しない。結果はUIの一時状態で、保存形式/schema/contentを変えず、次の確定ゲーム行動・リセット・成功した復旧で消す。新しい待機を優先する。マップへ戻る操作は選択地点だけを現在地へ合わせ、ゲーム遷移・乱数更新・保存を呼ばない。再読込後にこの一時結果パネルを復元しない。終了時の振り返りは別の永続的な構造化記録から作る。

イベントUIはネイティブボタンと `aria-describedby` で費用・収穫・理由を関連付ける。狭幅は3択を縦に並べる。解決は同じ上部領域の結果見出しへフォーカスし、結果内のボタンから現在地へ戻れる。終了した結果からは終了見出しと新しい探索へキーボードで進める。外部由来のログ・通知文字列は `innerHTML` へ埋める前にエスケープし、保存原文はUIへ表示しない。

## 配信

`npm run build` で `dist/` を生成。`base: './'` により GitHub Pages のリポジトリ配下などのサブパスでもアセットを読み込める。クライアントルーターは使わず、サーバーの URL 書き換え設定は不要。

実行時は外部通信・API キー・DB が不要。開発時に npm レジストリが必要。Cloud の `/usr/bin/chromium` をブラウザテストに利用する。GitHub Actions では Playwright 管理の Chromium をインストールして同じテストを実行する。

公開先は GitHub Pages。`.github/workflows/pages.yml` の build ジョブが検証済み成果物をアップロードし、依存する deploy ジョブが公開する。PR では検証のみ、`main` への push と手動実行では公開まで行う。Actions は公式リポジトリのコミット SHA で固定する。公開ジョブにのみ `pages: write` と `id-token: write` を付与する。初回の Pages 有効化はリポジトリ設定で行う必要があり、通常の `GITHUB_TOKEN` での自動有効化は前提にしない。

所持品操作後のフォーカス復元は `.drawer-scroll` のスクロール位置も調整する。上端で容量超過の警告が消える場合は、その操作中だけ警告の高さを保持し、使用ボタンが上へ飛ぶことを防ぐ。通常のメニュー移動でこの表示用の余白を解除し、保存データには含めない。地形の正方形画像は地点バナー内で比率を保って切り抜き、横長へ引き伸ばさない。
