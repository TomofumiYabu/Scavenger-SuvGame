# 技術構成

## 採用

| 要素 | 選択 | 理由 |
| --- | --- | --- |
| 言語 | TypeScript / strict | 状態、行動、セーブ形式を型で明示できる |
| UI | HTML + CSS + SVG | ターン制マップと情報パネルに適し、キーボード操作やレスポンシブ対応が容易 |
| 開発・配布 | Vite | 軽い開発サーバーと静的ファイルへのビルド |
| ルール検証 | Vitest | DOM なしで行動・資源・勝敗・保存検証をテスト |
| 操作検証 | Playwright + Cloud 標準 Chromium | ビルド成果物の実操作、保存復元、モバイル幅を確認 |
| 保存 | localStorage / schema 2・content 2 | バックエンド不要。端末間同期は対象外 |

Node.js 24.19.0 / npm 11.9.0 を Cloud で使用。npm キャッシュは `.npmrc` でチェックアウト内の無視対象 `.cache/npm` に配置する。新規導入で lockfile を作成し、以後 `npm ci` で再現する。

React などの UI フレームワークや Phaser / Godot は、現段階の小さなターン制 UI には導入しない。アニメーション、戦闘、広いマップが必要になった時点で再評価する。ルールと UI の分離によって描画方式を変更しやすくする。

## ディレクトリ

```text
AGENTS.md              開発ルール
docs/                  仕様・設計・進捗・Cloud 操作手順
src/game/              型、固定マップ、行動処理、セーブ検証、ユニットテスト
src/main.ts            スタイル読込とUI起動
src/ui/                テンプレート、DOM更新、入力・保存接続、フォーカス、結果表示
src/style.css          レスポンシブな画面
public/                配布する静的アセット
tests/                 本番ビルドに対するブラウザテスト
dist/                  配布成果物（Git 対象外）
```

## 状態と処理

入力 → `act(state, action)` → 新しい状態 → 保存 → 再描画。ルール関数は入力を変更しない。不可能な行動は状態を変えない。乱数は状態に保持する固定シードの疑似乱数で、再現可能にする。未探索地点と探索済み地点を別々に管理する。

`src/game/actions.ts` の DOM に依存しない `actionTerms()` に、時間、能力値の消費・回復、所持品の消費、収穫、負傷率、乱数更新の有無を集約する。`SEARCH_METHODS` は探索2方式の表示名・時間・費用を定義し、地形ごとの通常収穫と慎重な探索の追加物資から実際の収穫を作る。`search.mode` は `quick` / `careful`。従来の内部呼び出しで省略した場合だけ `quick` とし、不正な方式は拒否する。コントローラーのDOM入力には有効な明示方式を必須とする。`assessAction()` は同じ値から実行可否・不可能な理由・状態に応じた危険・負傷を含まない確定的な行動後の能力値を返す。`canAct()` とUIの disabled / 説明表示はこの判定を共用し、`act()` は同じ費用・回復値を適用する。共通の純関数 `projectStats()` が上限までの回復、負傷、時間で等分した毎時の消費と、各時間の消費後に0になった満腹度・水分それぞれの体力−12を計算する。従来の1時間行動と0時間の立ち去りの結果を維持する。2時間の探索も全時間・収穫・探索済みを一括確定し、途中状態のUI・保存・中断は導入しない。死亡、送信成功、時間切れの順に解決する。必要時間が残り時間を超える行動は拒否し、ちょうど48時間の終了は許可する。手早い探索は従来どおり全地形で乱数を1回進め、廃墟でだけ3分の1の負傷を判定する。慎重な探索は負傷抽選・乱数更新をしない。イベントの危険な選択の乱数更新も維持し、案内では乱数を参照しない。プレビューは入力を変更せず、保存形式への追加もない。

UIは案内をボタンの近くに常時表示し、`aria-describedby` で関連付ける。探索の各方式は別々の `data-focus="search-quick"` / `search-careful` と `guide-search-quick` / `guide-search-careful` を持ち、DOM更新で異なる方式に同じボタンを流用しない。ネイティブの disabled ボタンを維持し、使用不能になった操作は近くの説明へフォーカスを移す。狭幅では所持品カードを1列にして、費用・回復・理由が折り返して読める幅を確保する。

マップは上頂点型六角形の odd-r offset（0始まりの奇数行を右へ半セル移動）。`neighbors()` を移動判定・発見・UIに共用する。IDは従来どおり `y * 7 + x`、座標名はA1〜G7で地形配置も維持する。UIはHTMLボタンを六角形にクリップし、幅の半分の行オフセットと高さの3/4の行間隔で敷き詰める。SVGの六角形線で選択状態とキーボードフォーカス（破線）を表示する。各ボタンは座標・現在地・探索済み・隣接状態を読み上げ、隣接地点には＋印も表示する。

`src/game/events.ts` の小さな型付き定義に、独自イベント3件の地形・文章・選択ID・費用・回復・物資消費・収穫・負傷有無・結果・一度だけの出現方針を持つ。`eventById()` / `eventForTerrain()` / `eventChoice()` で保存検証・発生判定・描画・選択を共用し、選択IDは該当イベント内で検索する。`actionTerms()` は通常探索の収穫と選択の費用・収穫も返し、UIと実行が共用する。`assessAction()` は未解決中の通常行動と古い選択を拒否する。エンジンは移動の終了判定後、生存・時間内かつ未解決の該当地形への入場時だけ待機を作る。選択待ちはイベントIDと現在地点、解決履歴はイベントIDで保持する。0時間の立ち去りは空腹・渇きの体力減少も抽選も行わない。通常探索の従来の乱数更新は維持し、イベント抽選は備蓄庫の危険な選択を確定した時だけ行う。診療所と避難所は乱数を使わず、回復・物資消費も通常行動と同じ共通項目で処理する。新イベントの結果は実回復量（上限適用）・時間・消費を定量的に記録する。避難所はSTART/B6の1か所だけなので、新規開始では発生せず、最初の帰還移動で発生する。

保存はschema 2・contentVersion 2で、キーを `afterlight.save.v2` に分ける。`save.ts` の `decodeSave()` はストレージに触れず、正常・旧版移行・破損・非対応を区別する。`deserialize()` はゲーム状態またはnullを返す互換窓口。値域、配列、勝敗、現在地、待機と解決履歴、既知のイベントIDを検証する。待機は現在地・対応地形・active・未解決を必須とし、解決IDは一意で最大3件。未知の内容版/イベントIDや、内容版1に新イベントIDが混在したデータは非対応として保護する。所持数は非負の安全な整数を認め、収穫が安全な整数を超える行動は拒否する。v1は元の資源・時刻・乱数・ログ・勝敗を保持して新フィールドを補う。v2/content1は同じ進行に加え備蓄庫の待機・解決を保持し、content2へ読み取りだけで移行する。現在地の六角形隣接発見は全対応版で冪等に補完する。読み込みではイベントを新たに発生させない。

`src/game/storage.ts` の `SaveStore` がストレージだけを担当する。読み込みはv2を優先し、存在するv2が不正/非対応ならv1へ戻らない。不正な原文は保護状態にして通常保存を止め、メモリ上の新規プレイを許す。読み込み自体は書き込まない。候補データを検証してから、読み取り可能な前のv2原文（旧内容版も可）を `.backup` へ書き、読み取り一致を確かめて主保存を更新する。v1移行直後は移行した初期状態をv2形式でバックアップしてから初回保存し、元v1原文は触らない。v2/content1を初めて更新する前は、原文を `.original.<連番>` へ永久退避し、読み取り一致を確認してから通常のバックアップ・主保存の書き込みへ進む。保存を重ねても退避は増やさず、失敗後の再試行でも同一原文の検証済み退避を再利用する。退避やバックアップの失敗なら主保存を変更しない。別タブなどで主保存が読み込み時から変わった場合も保護する。

復旧は検証済みバックアップ（読み取り時に移行する旧版も可）を対象とし、UIの確認後に実行する。復旧/新規探索で主保存を切り替える際は、その時点の原文を `.original.<連番>` へ退避し、読み取り一致の確認後だけ主保存へ書く。既存退避と旧v1は消さない。読み込み/書き込み/読み取り確認の失敗時は通知し、通常保存を停止する。localStorageの書き込み単位の原子性を利用し、複数キーのトランザクションは仮定しない。主保存の書き込み後の確認が失敗した場合は切り替え完了を保証せず、元データをバックアップ/退避に保持する。複数タブ間の競合を完全に排除する同期機構は持たない。

UIは `src/ui/controller.ts` が明示的なゲーム状態・選択地点・UI専用の結果と `SaveStore` を保持する。`main.ts` は起動だけを担当する。`templates.ts` は渡されたコンテキストから画面と行動案内を作り、起動時のダイアログシェルを提供する。`render.ts` はネイティブDOMを差分更新し、変更のない要素を保持する。通知・終了・イベント/結果には固定の領域を用意し、その追加・削除で後続のマップや所持品を置き換えない。要素名とID・操作キーが変わる要素は交換し、異なる操作へ同じボタンを流用しない。属性・テキスト・子要素だけを必要に応じて更新する。`details.open` はライブDOMに保持し、保存不能へ変わった時だけコントローラーが説明を開く。フレームワークと追加依存は使わない。

`focus.ts` は実際の操作ボタン・操作キー・関連説明・近くの領域とスクロール位置を記録する。通常更新は存続する操作へ `preventScroll` で戻し、上部の結果が消えた場合も対象の画面内位置を補正する。ボタンがdisabledなら関連説明、削除されたら地点の行動領域などへ戻す。代替対象が画面外なら最小限表示する。イベント/結果/終了の見出しと明示的なマップへ戻る操作は、フォーカスとスクロールを意図的に移動する。ネイティブダイアログのキャンセル/閉じる時は実際の起動ボタンと位置を復元し、リセット/復旧確定時は復元を抑えて読み込んだ状態へ移す。

`outcome.ts` はイベント定義から選択名と結果文を取得し、実際の前後のゲーム状態から時間・能力値・物資の差分を作る。ログはエンジンのstructuredCloneで参照が変わり12件に制限されるため、前ログの先頭と後ログの末尾の最大一致をturn/text/kindで比較し、新しい危険だけを取り出す。単なるログ件数差を使わず、0時間の選択でも過去の危険を再掲しない。結果はUIの一時状態で、保存形式/schema/contentを変えず、次の確定ゲーム行動・リセット・成功した復旧で消す。新しい待機を優先する。マップへ戻る操作は選択地点だけを現在地へ合わせ、ゲーム遷移・乱数更新・保存を呼ばない。永続的な根拠は従来の探索の記録で、再読込後に結果パネルを復元しない。

イベントUIはネイティブボタンと `aria-describedby` で費用・収穫・理由を関連付ける。狭幅は3択を縦に並べる。解決は同じ上部領域の結果見出しへフォーカスし、結果内のボタンから現在地へ戻れる。終了した結果からは終了見出しと新しい探索へキーボードで進める。外部由来のログ・通知文字列は `innerHTML` へ埋める前にエスケープし、保存原文はUIへ表示しない。

## 配信

`npm run build` で `dist/` を生成。`base: './'` により GitHub Pages のリポジトリ配下などのサブパスでもアセットを読み込める。クライアントルーターは使わず、サーバーの URL 書き換え設定は不要。

実行時は外部通信・API キー・DB が不要。開発時に npm レジストリが必要。Cloud の `/usr/bin/chromium` をブラウザテストに利用する。GitHub Actions では Playwright 管理の Chromium をインストールして同じテストを実行する。

公開先は GitHub Pages。`.github/workflows/pages.yml` の build ジョブが検証済み成果物をアップロードし、依存する deploy ジョブが公開する。PR では検証のみ、`main` への push と手動実行では公開まで行う。Actions は公式リポジトリのコミット SHA で固定する。公開ジョブにのみ `pages: write` と `id-token: write` を付与する。初回の Pages 有効化はリポジトリ設定で行う必要があり、通常の `GITHUB_TOKEN` での自動有効化は前提にしない。
