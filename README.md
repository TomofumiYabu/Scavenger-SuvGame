# AFTERLIGHT — 残光の街

荒廃した近未来都市を探索し、物資を集め、最後の救難信号を送る。一人用・日本語のターン制サバイバルゲームの試作です。静的サイトとして配信でき、ゲーム実行にサーバーやアカウントは不要です。

## 現在できること

7行×7列の六角形マップを6方向に探索・移動し、満腹度・水分・気力を管理します。容量24のバックパックに8種のアイテムを持ち、休息や通信塔からの脱出を行えます。探索や出来事で見つけた物資は現在地に残り、必要な分だけ容量24のバックパックへ拾います。満杯でも探索できます。所持品は現在地に置け、残した物は再訪・再読込後も保持します。拾う・置く操作は0時間で、イベントの選択待ち・探索終了中はできません。栄養バー、電解質飲料、救急キット、濃縮コーヒーを含む8種の所持品の用途と容量はゲーム内で確認できます。

探索では、1時間で気力10・満腹度5・水分6を消費する「手早く探す」と、2時間で気力16・満腹度10・水分12を消費する「慎重に探す」を選べます。慎重な探索では、手早い探索より主要物資を1個多く、さらに地形に応じた新アイテムを1個発見します。地点ごとにどちらか一度だけ探索できます。廃墟を手早く探すと負傷することがあり、慎重な探索では探索による負傷はありません。各時間の消費後に満腹度・水分が0なら、その資源ごとに体力が12減ります。移動・休息・アイテム使用など他の通常行動は1時間です。

廃墟の「崩れた備蓄庫」、診療所の「残された処置台」、避難所の「消えかけの火」の3つの選択イベントがあります。避難所イベントは開始地点B6から初めて避難所へ戻った時に始まり、新しいゲームの開始時には発生しません。いずれも1プレイにつき一度だけで、未解決の選択は再読込後も続きます。

ブラウザ内に自動保存し、次回は続きから再開します。以前の四角形マップのv1セーブを含む旧保存は、所持品・探索履歴・イベント状態・乱数を引き継ぎます。移行時に探索済み地点の物資を再生成せず、元の保存データを保持します。ひとつ前の保存へ戻すこともできます。容量を超えた旧セーブの所持数も保持し、容量を増やさない行動を続けられます。戦闘とクラフトは今後の候補です。

行動ボタンのそばで、時間・資源消費・回復量と実行できない理由を確認できます。資源が尽きる行動、廃墟での負傷、救助期限に達する行動には、実行前に危険を表示します。

イベントの選択後は、実際の変化と危険を確認してからマップへ戻れます。戻ると現在地のタイルが選択されます。

## Codex Cloud で開発

ユーザーのローカル PC に環境を構築する必要はありません。以下はすべて Cloud ターミナル内で実行します。

```bash
cd /workspace/Scavenger-SuvGame
npm ci
npm run dev
```

開発サーバーはポート5173。本環境のオンボーディング画面ではブラウザ用プレビューリンクを提供できないため、Codex が Cloud 内の Chromium で表示・操作を検証します。

```bash
npm run check
```

ユニットテスト → 型チェック → 本番ビルド → ブラウザテストを実行します。Node.js 24.19.0、npm 11.9.0、Cloud にある `/usr/bin/chromium`、Python 3 を使用します。Python は静的サブパス配信のテスト用で、製品の依存ではありません。秘密情報や環境変数の追加は不要です。

## 配布

```bash
npm run build
```

公開先は GitHub Pages。[ブラウザで遊ぶ](https://tomofumiyabu.github.io/Scavenger-SuvGame/)。2026-10-16にユーザーが設定と動作確認を完了しました。確認の範囲は [進捗](docs/PROGRESS.md) に記録しています。

`main` にプッシュすると GitHub Actions が依存導入、ユニットテスト、型チェック、ビルド、ブラウザテストを行い、成功した `dist/` を公開します。Pull Request では検証だけを実行します。初回の Pages 有効化と、公開の確認方法は [公開手順](docs/DEPLOYMENT.md) を参照してください。

生成される `dist/` の**中身すべて**（`index.html`、`assets/`、`favicon.svg`）が配信対象です。サブディレクトリ配信に対応し、URL 書き換えは不要です。HTTP/HTTPS 配信を前提とし、`file://` で直接開く使い方は対象外です。

公開後のプレイに外部 API/CDN への通信はありません。セーブはブラウザのlocalStorageに保存され、任意のファイル入出力や完全なタブ間同期には対応していません。ブラウザのデータ削除や配信元の変更で失われる可能性があります。
